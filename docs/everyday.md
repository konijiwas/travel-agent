## 二、最有价值的总结

### 核心技术收获(每条都经过实战验证)

1. **确定性设计是 AI 项目可测的基石** —— mock 数据哈希派生、fake 规则解析、质量门硬校验,让"同一个输入永远同一个输出",评测/调试/演示不再有玄学。凡是能用规则定死的,不交给 LLM 自由发挥。

2. **数据模型先行,契约即文档** —— 每个 Agent 开工前先定 Pydantic 模型(TripRequirement → BudgetPlan → Itinerary → AgentMessage);提示词规则 = fake 生成器规则 = 质量门规则 = 测试断言,四方对齐,双模式(真实 LLM/离线规则)行为一致。

3. **"LLM 生成 + 规则校验"的混合架构** —— LLM 负责编排与决策建议,确定性代码负责质量门六项校验(需求完整/预算偏差≤10%/冲突/可追溯/天气标注/数据来源)。质量门失败定向回退重试,重试仍败降级交付——保证端到端完成率。

4. **分层解耦:Agent 依赖数据,不依赖数据来源** —— M2 建服务、M3-M5 建 Agent、M6 才接线,每步独立验证;数据"注入"而非"工具调用",接口抽象(队列 Protocol)让 Redis/内存无缝切换。

5. **可靠性从第一天就内建** —— 幂等 key(重发不重复)、超时+熔断(单源故障不拖垮全局)、崩溃恢复(至少一次投递)、权限分级(10% 阈值交人工)、全程留痕(四要素/三要素台账)。

### 踩过的最有价值的坑(全部按"最小实验实测 → 定位 → 修复"解决)

| 坑 | 教训 |
|---|---|
| typer 两个版本在本环境位置参数解析全坏 | **框架版本行为差异,先写 10 行最小实验实测,不猜** |
| click 8.2 与 typer 0.17 不兼容 | 依赖必须锁版本区间,且注意"版本配对" |
| checkpoint-sqlite 2.0.10 serde API 与 langgraph 1.2 不匹配 | SQLite 路径要真实走到才会暴露——测试覆盖所有生产路径 |
| langgraph 1.x interrupt 返回 `__interrupt__` 键而非抛异常 | 版本升级的行为变化,以实测为准 |
| 生产 CLI 与测试共用 Redis db 0 互相污染 | **测试环境与运行环境必须隔离**(测试用 db 1) |
| 抵达日晚到导致活动时间重叠 | "部分动态、部分写死"的规则必然在边界咬合出 bug——测试用真实数据逼出来,修复只需 3 行 |
| fake 解析器把提示词 few-shot 示例当用户输入 | 解析器只取 human 消息;系统提示词与用户数据严格分离 |

### 方法论沉淀(照这个套路 M7-M10 继续)

1. **里程碑制**:每个里程碑有独立交付与验证命令,pytest 全绿才进入下一个;一次只引入一个变量
2. **测试即文档**:测试 docstring 写金额推演/场景意图;断言钉死精确值(确定性设计的红利)
3. **每步提交**:M1-M6 六次独立提交,历史可追溯、可回退
4. **开闭原则**:注册表/契约/常量表——加新功能只加一行,不改老代码
