# M9 消融实验与复盘

> 运行时间:2026-10-08 · 模型:deepseek-chat(真实 LLM,非 fake 离线)· 评测集:15 条 case
> 命令:`uv run python -m travel_agent.main ablate`

## 一、目标与方法

**消融实验(ablation study)** 回答一个朴素的问题:系统里的每个功能,到底贡献了多少?

做法是"控制变量":同一套 15 条评测 case,先全功能跑一遍作**基线**,然后每次**只关掉一个功能**重跑一遍,对比通过率变化——掉分的功能是"承重墙",不掉分的说明它在当前评测下不承重(可能是架构层,也可能是评测没覆盖到)。

本次消融的 4 个开关(均为 env 控制,`True = 关闭对应功能`):

| 开关 | 关掉的功能 | 消融方式 |
| --- | --- | --- |
| `TA_ABLATE_BUDGET_ADJUST` | 预算超支自动调整 | 提示词级:不检测超支、不调整、不挂起确认 |
| `TA_ABLATE_WEATHER` | 天气影响行程变更 | 提示词级:不替换/改期室外活动,但仍标注天气 |
| `TA_ABLATE_QUEUE` | 消息队列解耦 | 代码级:换 `NoOpQueue` 空队列 |
| `TA_ABLATE_SMALL_GATE` | 质量门把关 | 代码级:质量门短路,直接交付 |

## 二、实测结果

| 配置 | 通过 | 通过率 | 相对基线 |
| --- | ---: | ---: | --- |
| 基线(全功能) | 15/15 | 100% | (基线) |
| 关掉 预算超支自动调整 | 14/15 | 93% | **-1 case** |
| 关掉 天气影响行程变更 | 14/15 | 93% | **-1 case** |
| 关掉 消息队列解耦 | 15/15 | 100% | 不变 |
| 关掉 质量门把关 | 15/15 | 100% | 不变 |

**结论:**

- **承重功能**(关掉即掉分):预算超支自动调整、天气影响行程变更。
- **架构/兜底层**(关掉不影响 happy-path 通过率):消息队列解耦、质量门把关。

## 三、掉分的是哪两条 case

通过对照 case 断言与消融指令语义,两条掉分的 case 可以精确定位(都在 `decision` 类):

| 关掉的功能 | 掉分的 case | 机制 |
| --- | --- | --- |
| 预算超支自动调整 | `decision-01`(预算 2000 去三亚 7 天,严重超支) | 该 case 断言 `first_interrupt_kind == "confirm"`、`confirm_asked == true`,依赖"超支 → 挂起用户确认"这条链路;关掉后预算规划师不再设置 `needs_confirmation`,确认挂起根本不触发,断言必挂 |
| 天气影响行程变更 | `decision-02`(杭州 2 天遇大雨) | 该 case 断言 `weather_changes_count >= 1`,依赖"雨天 → 室外改室内并留痕";关掉后 `weather_changes` 恒为空,断言必挂 |

也就是说:**两条决策规则各对应一条 decision 类 case,关掉即掉分**;其余 13 条(normal/boundary/error/security)不依赖这两条规则,所以不动。

## 四、解读:为什么队列、质量门"不掉分"

不掉分 ≠ 功能没用,而是**评测视角的局限**。当前 15 条 case 以 happy-path 为主:

- **队列**的价值在**解耦与留痕**(事件广播、消息持久化、幂等去重),状态机主流程由 `state` 驱动、不依赖队列,所以关掉队列对"能不能规划出正确行程"无影响——这恰好印证了架构设计:队列是**横切能力**,不是正确性的承重墙。
- **质量门**的价值在**拦截缺陷**(回退重试、降级交付标注),但当前评测集里没有"能产出结果但质量不达标"的 case,所以关掉质量门在现有 case 上自然无差别。

这本身就是一个有价值的结论:**架构层的投入,需要对应的评测场景才能被量化**。若要证明队列/质量门的价值,需要在评测集中补充"质量门故障""队列故障/重放"类 case(见第六节)。

## 五、设计与实现说明(诚实记录)

1. **第 4 个开关的落地与计划略有出入**。计划文档把 `TA_ABLATE_SMALL_GATE` 描述为"需求分析换小模型",实现时按开关名落地为"质量门把关"(短路质量门直接交付);"需求分析换小模型"另留 `analyst_model` 配置项,未纳入本次消融。二者同属架构层,对 happy-path 通过率均无影响。
2. **预算/天气消融作用于提示词,必须真实 LLM 模式才有效**。fake 离线模式的解析器不读提示词,跑不出退化;故 `ablate` 命令在 `eval_mode == "fake"` 或无 API Key 时直接报错退出,避免产出无意义的对照表。
3. **跑完自动恢复开关状态**。`run_ablation` 用 `try/finally` 保存并还原 4 个开关,不污染同进程后续调用(测试友好)。

## 六、局限与后续

- **评测集偏 happy-path**。error/security 只覆盖了少量故障注入,队列、质量门的真实价值(故障隔离、缺陷拦截)无法被当前 case 量化。这是"0 掉分"结论的主要边界。
- **消融的粒度是"整功能"**。预算/天气都是"整条规则"级别的开关,未做更细的梯度消融(如只关优先级链第②步)。
- **后续建议**:① 增补 `quality_gate_fail`、`queue_fail` 类 case,量化架构层价值;② 增补换小模型(`analyst_model`)的 cost/latency 对照,补全第 4 类消融;③ 把 retro 里的实测百分比替换进简历(M10)。
